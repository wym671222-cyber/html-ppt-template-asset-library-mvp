## 交付

1. `0006_p14_presentation_ownership.sql` 为 `presentations` 新增非空 `owner_user_id -> users.id` FK、`presentations_owner_updated_idx`、owner 必填与不可变 trigger；journal、schema、目标 trigger allowlist 与 recovery ledger 均升级为第 7 条 migration。
2. 迁移预检在备份之后、执行 P14 之前计数 `presentations/presentation_items/presentation_exports`；任一非零即列出表名/计数并拒绝，不写 owner、不跑第 7 条 migration。未知/不完整 trigger 仍先备份后拒绝。
3. `OwnerContext` 改为经严格 user id 验证的用户上下文，仅由服务端验证 session 派生。业务 JSON 中任一 `owner|ownerId|ownerUserId|userId` 均拒绝，浏览器无法选择所有者。
4. catalog 和安全 PNG 对所有 active、已改密用户共享，且 catalog 响应不暴露 owner。Presentation/Item/Export 的 list/read/create/rename/add/copy/move/override/delete/export/readback 均以当前 session user 过滤；未登录 401、强制改密 403、跨用户 404，admin 无任何内容绕过。
5. Export audit manifest 升级为 `html-presentation-export/v2`，ZIP 内嵌 manifest 升级为 `html-presentation-export-package/v2`，两者固定 `ownerUserId`。owner 纳入 export fingerprint，每次 list/read/download 与 recovery 都以 DB owner、audit manifest owner 和 ZIP owner 三方重验。
6. Recovery 是全局 admin-only 能力：未登录 401，member 或 `must_change_password=true` 的 admin 为 403；恢复概览不暴露 fixed owner。backup manifest 为每个 Presentation/Export 固定 `ownerUserId`，恢复时用 v2 repository 回读并重验。
7. 隔离恢复先证明原始备份逻辑状态一致，再删除恢复库全部 session 并重验；发布恢复目录前同时删除源库全部 session。测试证明原有 admin/member session 和旧 admin Cookie 全部失效。
8. `tests/p14-user-ownership.test.ts` 覆盖 A/B 共享 catalog/PNG、完整 Presentation/Item/Export CRUD/排序/隔离、admin 无绕过、owner 输入拒绝、manifest v2 回读/ZIP/recovery、recovery 权限与全会话撤销、无秘密，以及空目标/三类非空阻断/未知 trigger/quick/FK/7 ledger/count。
