## 完成内容

1. 新建本机 SHA-256 CAS。对象写入到忽略的 `apps/api/data/objects/sha256/<prefix>/<digest>`；先写同目录临时文件并 fsync，再以 hard link 原子落位。相同内容只保留一个对象，不同内容由 digest 隔离；读取和遇到既有对象都会校验内容哈希。
2. P03 适配器现在同时保留规范化 source，并导出其稳定字节序列化。`AssetCatalogRepository` 只将该序列化内容写入 CAS，并拒绝 CAS digest 与 P03 `sourceDigest` 不相等的输入。
3. 资产登记将 `content_objects`、`template_assets`、不可变 `template_versions`、tag 关系和 current verified version 放入单一 SQLite 事务。完全相同的登记幂等；任何既有 asset/version 元数据或内容冲突均拒绝。
4. 提交 `0001_p04_catalog_jobs.sql`。它保留编号迁移与已有 Job 历史，把旧 pending 前身安全映射为 `pending`，并为单机租约增加 `max_attempts`、lease owner/expiry 与查询索引。
5. 新建 SQLite `LocalJobRepository` 与不联网的 `LocalJobWorker.runOnce()`：只允许持有 lease 的 Worker 成功或失败，租约到期可恢复，超过重试上限转失败，成功输出必须引用现有内容对象，成功后不可被失败重试覆盖。
