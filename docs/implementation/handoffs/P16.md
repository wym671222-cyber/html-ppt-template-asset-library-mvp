## 交付

1. API/Web systemd 候选都以非 root `htmlppt` 和精确 `/usr/bin/node` 运行。API 固定 `127.0.0.1:3001` 且独占 `/var/lib/html-ppt` 写权限，并默认 `APP_READ_ONLY=true`；只有 P17 开放写入前门禁通过后，才允许由 preflight 核验的非 symlink、`root:root 0600` `/etc/html-ppt/api.env` 与显式 `--allow-write-override` 放行。Web 固定已记录 bridge `172.18.0.1:4173`。两者固定 `ORIGIN=https://ppt.ajjy-ai.site`、`UMask=0077`、只读 release 与 systemd hardening。
2. 生产数据路径由 `ASSET_LIBRARY_DATA_ROOT=/var/lib/html-ppt` 显式锁定；DB、objects、recovery/backups 均在数据根内。非生产仅允许规范化绝对临时根，开发默认仍保持仓库 API data 路径。
3. 迁移器先读取 migration 文件并计算 pending 数；只有“既有 DB 且确有 pending migration”才产生 pre-migration 备份。完全迁移库重复运行不会制造备份，隔离测试已更新旧阶段预期。
4. 生产 Caddy 候选固定精确站点、自动 TLS、安全头、0600 JSON 轮转日志、主动 `/api/health/ready`，对 HTML 使用 `no-cache`，对 `/_app/immutable/*` 使用一年 immutable。发布脚本以 no-clobber 方式把旧 release 的 hash 资源累积到新 release。
5. WorkBuddy `preflight/deploy/rollback/smoke` 脚本与人工手册固定完整 40 位 SHA、`/opt/html-ppt/releases/<commit>`、原子 `current`/`previous` symlink、精确 `/usr/bin/node` 22/pnpm 9.15、权限/数据/健康检查和回滚边界。deploy/rollback 没有默认 production target；deploy 还要求 `--approved-commit` 与 `--commit` 完全相同。脚本不会自动启停服务、迁移、reload Caddy、删除旧 release/备份或连接远端。
6. Migrator 与生产 preflight 共用 `apps/api/drizzle/schema-trigger-contract.json`，分别构造 5、6、7 条 migration ledger 的精确 trigger 集合；两者都读取实际 ledger count 并只接受对应唯一集合。缺失、错 ledger 集合或其他 ledger count 统一 fail closed；ledger 绑定错误不输出具体差异值，外部 verifier 也不输出 DB 内容或 trigger 明细。
7. CI 保持 all-branch frozen install、类型/单元/shell、adapter-node Web build、P16 演练和 Chrome E2E；不含部署 job、服务器地址凭据或自动生产写入。

## adapter-node 真实客户端地址信任边界

`ADDRESS_HEADER=x-forwarded-for` 与 `XFF_DEPTH=1` 只允许用于已证明的单跳拓扑：浏览器只能到受控 Caddy，Caddy 再连接 Web；4173 不得被浏览器或其他代理直达。候选 Caddy 先删除 `Forwarded`、`X-Real-IP` 和入站 `X-Forwarded-For`，再用该连接的 `{remote_host}` 写入单值 XFF。

P16 演练用受控单跳代理发送浏览器伪造的 `X-Forwarded-For: 203.0.113.77`，随后直接回读隔离 SQLite 的持久限流键：受信地址对应 `127.0.0.1`，伪造地址对应 key 不存在。若 P17 现场发现 bridge 不再是 `172.18.0.1/16`、存在 CDN/负载均衡器/第二代理、Caddy 不能覆盖入站头或 4173 可被浏览器直达，必须保持 Web 未启动并 fail closed；不得猜测 `XFF_DEPTH` 或改成公网 bind。
