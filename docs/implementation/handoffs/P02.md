## 完成内容

1. 建立 API 新产品 composition root；仅保留根、health 和固定 Owner 端点。`serve` 明确绑定 `127.0.0.1`。
2. 建立固定、请求无关的 `OwnerContext`，不读取 cookie、header、User、角色或 approval 状态。
3. 将活动数据库边界固定为 `apps/api/data/asset-library.db`，拒绝替换 `DATABASE_URL`，并提交 Drizzle SQL migration `0000_p02_foundation.sql` 和 journal。
4. 建立 `content_objects`、模板资产/版本/标签、presentation/item、jobs、audit 目标 schema；SQL 约束和触发器表达 P01 ADR 第 6 节的 P02 可验证不变量。
5. 在迁移前对现有目标库执行只读 quick_check/foreign_keys/table preflight；存在时复制备份并记录 SHA-256；存在未知表则在备份后停止，不转换、不 drop/reset。
6. 将 Web 绑定为 loopback，活动根页不依赖身份；hook 层拒绝非 loopback Host/Origin 和旧路径，且移除旧 `/api` proxy。
7. 新增 P02 单元、运行时负向和独立端口 E2E 测试；修正现有 shell 类型检查直接使用已安装的 local `tsc`，避免 pnpm 10 在检查时触发生命周期审批。

## 数据与安全边界

- 没有建立 `users`、`organizations`、`role_bindings`、approval/RBAC 表，也没有任何 `owner_id` 多租户预埋字段。
- 旧 auth/admin/sharing/presence/lock/provider 代码未删除，但不被活动 API 组合根导入或挂载；旧 Web 页面由 hook 阻断。
- 空库及已有目标库的 migration 均可重复执行；未知旧数据库（单测 `users`）必然先备份后停止。
- 已验证/可用 `TemplateVersion` 的内容字段不可更新或删除；`current_version_id` 必须指向同 asset 的 verified/available version；`PresentationItem` 固定版本且只允许 declared slot；content/audit 追加写入。
- 本阶段不创建模板数据、对象写入、Job 执行、Chromium 预览、资产 UI、Presentation 旅程或导出。
