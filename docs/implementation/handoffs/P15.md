## 交付

1. Web 仅通过同源 `/api/*` BFF 访问 loopback API；BFF 只转发 Cookie/Set-Cookie，浏览器永不直接使用 API origin。
2. 写入 BFF 在转发前严格校验单一精确浏览器 Origin、`application/json` 和 16 KiB 有界流式 body；删除全部入站客户端转发头，仅从 `getClientAddress()` 规范化派生单值 `X-PPT-Client-IP`，再写入受控 API Origin。
3. 新增用户名注册、登录、等待审批、强制改密和管理员审批/停用/重置页；所有活动身份页使用中文标题，无邮箱输入。身份表单在 hydration 前保持 `aria-busy`、禁用提交，并在交互就绪后标记 `data-auth-ready="true"`，避免 CSP `form-action 'none'` 下的原生冷启动提交。登录根据服务端 `mustChangePassword` 导航，改密的 204 与清除 Cookie 被正确透传。
4. hooks 只为页面路由门读取 session；`/_app`、health 和 BFF API 不产生额外 session 查询。匿名改密重定向登录，强制改密用户重定向改密，admin/member 路由分别受门控。
5. 资产库 header 展示用户与退出；所有 password-ready active 用户加载个人 Presentation。member 不请求 admin-only recovery，admin 展示实际 `migrationCount`。保留 P14 共享 catalog/PNG、Presentation 跨用户 404、admin 无内容绕过和 recovery 权限。
6. P15 隔离 HTTPS Chrome fixture 只使用 P03 fixture 和临时 SQLite/CAS，验证 Secure cookie、注册→待审批→admin 批准→登录→个人 Presentation→导出→退出、A/B 隔离、旧 session reset 撤销、临时 session 改密撤销、新密码重登、移动 member/admin、无邮箱表单、中文 title、键盘焦点与错误焦点。重置用例独立注册并审批其成员，不依赖前一用例状态。
