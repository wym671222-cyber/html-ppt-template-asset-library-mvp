## 生产身份与验收目标缺口

即使恢复目标访问，当前仓库证据仍不足以安全执行 P07 写入：

2. 项目基线记载生产曾有 30 个活动模板（15 Workshop + 12 静态组件 + 3 合同续签），终局要求 27（15 + 12）。若线上仍是该 30 项基线，把十二个合成 ID 当作新资产导入并只退役三个目标会得到 39，而不是 27；要安全达到目标，必须把每个批准 v2 包精确映射到既有十二个静态组件资产并在同一资产下晋升版本，或由父级提供另一份经生产核验的权威映射。仓库内没有这份 12 对 12 映射。
3. 用户批准的 v2.0 计划已明确给出三个精确退役 `assetId`：`html-4d353ff9f58e974d4e8a`、`html-ef7410b3f4732cb7df31`、`html-221e1002d8e216bfefde`。它们不是当前 blocker；在目标访问恢复后仍需由管理员会话核对其当前状态与审计，但 P05 测试退役的前三个合成 fixture 不能替代这三个生产目标。
