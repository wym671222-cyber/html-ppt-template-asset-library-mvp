- 父级在原候选 `f17a8d0a16cbc453947ed84f9519142276db6dfc` 上用真实 Google Chrome 证明：即使 runtime 响应包含 `default-src 'none'`、`connect-src 'none'`、`frame/child/object/form/base` 全拒绝、`navigate-to 'none'`、响应级 `sandbox allow-scripts`，且父 iframe 精确为 `sandbox="allow-scripts"`，内层 `location.href` 仍让第二个 `127.0.0.1` 随机端口收到 `/escaped?secret=1`。顶层未跳转，但子框架已完成网络外泄，因此父级门禁失败。

## 实现内容

1. 新增共享 runtime 协议：`html-template-runtime/v1` 的精确 `ready/error/replay/reset` schema、32 个十六进制字符（128-bit）的随机会话 ID、单调命令序号、响应头常量及严格 CSP 构造/解析器。
2. runtime 编译器每次请求重新执行 P01 v2 安全策略、规范化摘要和仓库白名单校验，并绑定 immutable TemplateVersion 的 asset ID、version 与 source/content digest；清单内 CSS/经典 JS 与已验证 `data:image` 被编译进 Base64 `data:` 模板文档，再由同一自包含响应中的可信 supervisor 承载，不产生 CDN、外链、blob、file 或 `srcdoc` 路径。
3. `GET /api/catalog/assets/:assetId/runtime` 只读取 authenticated owner 可见的 `active` 资产、`current_version_id` 指向的 `verified/available` `html-template/v2`、白名单摘要和通过 CAS 元数据/字节摘要复验的规范化包。v1、非 current、retired、未知、非白名单、错误 digest/CAS 和带查询参数的请求全部 fail closed。
4. runtime 响应使用随机 nonce，并精确拒绝默认资源、connect/media/font/worker/manifest/object/base/form/navigation；frame/child 只允许初始化内部自包含 `data:` 文档，拒绝所有网络 scheme、`'self'` 与通配符。外内两层均精确应用 `sandbox allow-scripts`，不含 `allow-same-origin`；响应仍为 private/no-store，模板因 opaque origin 无法读取站点 Cookie 或存储。
5. runtime supervisor 只接受来自 UI `parent`、匹配祖先 origin（可取得时）、匹配随机 session、精确键集合且序号严格递增的 replay/reset 命令；只转发来自精确内层 `contentWindow`、opaque `null` origin、匹配 session/asset/version/source digest 的 ready/error。`navigation-blocked` error 由 supervisor 自身产生并绑定原 session；任意额外字段、伪造 session、错误来源和重放序号均不是命令。
6. 新增唯一精确 Web BFF runtime 路由。BFF 只接受 API 返回的完整静态安全头、精确 CSP、协议与会话格式，重建响应头并丢弃包括 `Set-Cookie` 在内的所有非白名单上游头；普通页面的既有 CSP 不被放宽。
7. v2 preview worker 在独立空 Cookie/存储 Chromium context 中运行：主服务仅绑定随机 loopback harness/runtime 两个 GET 路径；另启第二个无限制 loopback 审计监听端口，并让 Playwright 对精确 fetch/self-navigation 审计 URL 执行 `route.continue()`，因此 `0 hits` 不是 `route.abort()` 的结果。worker 在晋升前主动验证 Cookie、local/session storage、父 DOM、父/顶层导航、弹窗、外网、自框架导航和伪造/重放消息全部受阻，并证明攻击后 supervisor 会话仍绑定。
8. worker 仍输出 1280x720 preview 和 320x180 thumbnail PNG；只有安全诊断、尺寸、真实 source/content digest 和 CAS 校验均通过后，才沿用 P01 同事务双派生物登记与高版本防回退晋升。v1 继续走原有 JavaScript disabled 的 P05 安全路径。

## 正负安全证据

- runtime 正向：P01 唯一白名单 fixture 在 v2 候选完成真实 Chromium 双派生物后晋升 current，随后 API 返回随机 session/nonce 的自包含断网页面。
- 版本与状态负向：v1 current、非 current v2、retired、未知资产、非白名单 current v2、带查询参数及被篡改 CAS 分别返回 404、400 或 409，不返回 runtime HTML。
- CSP/BFF 负向：绝对外部 URL、查询串和额外路径层级在 fetch 前被拒；把 `connect-src 'none'` 改成外部连接或加入 `allow-same-origin` 会使安全头验证失败；错误 session 被拒；上游 `Set-Cookie` 不跨代理。
- 消息负向：错误 session 不改变 runtime，重复 sequence 被拒，随后正确更高序号 replay 成功；ready 同时绑定 iframe source、opaque origin、session、asset/version/source digest 和精确 schema。
- self-navigation 负向：真实 Chrome 在模板上下文执行外部 `location.href`；第二监听端口 `selfNavigationAuditHitCount=0`，并收到 source/session/identity 绑定的 `navigation-blocked` error。把该诊断伪造为 `1` 会让 Job 失败、零派生物且 v1 current 不变。
- Chromium 隔离：证据字段确认 Cookie header/context/document、localStorage、sessionStorage、父页面 DOM、父/顶层 location/navigation、popup、fetch 与 self-navigation 均不可用；外内 iframe sandbox 均精确为 `allow-scripts`，两层 origin 均为 opaque；第二监听端口的 fetch/self-navigation 两个审计计数均为 0，攻击后 runtime context 仍绑定。
- 派生物：preview/thumbnail 均绑定 P01 source digest、同一 `p02-chromium-v2:<browser>` renderer 与同一安全诊断，CAS 回读 PNG 尺寸分别为 1280x720 和 320x180。
- v1 回归：既有 P05 JavaScript-disabled 路径和两项真实 Chromium 安全测试保持通过。
