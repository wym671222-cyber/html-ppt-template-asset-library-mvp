## 父级第一次有界修复（已完成）

父级独立门禁发现：原 `recordRender()` 只证明 preview/thumbnail 彼此使用同一个调用方摘要，没有先证明该摘要属于目标 TemplateVersion；SQLite 外键只能证明摘要对应某个 content object，不能证明版本归属。

本次唯一有界修复严格限制在 `preview-jobs.ts`、PocketBay 导入测试、本 handoff 与 STATUS：

1. `recordRender()` 在同一事务的第一步核对目标版本存在且状态为 `verified/available`，并要求调用摘要同时严格等于该版本的 `source_digest` 与 `content_object_digest`；任何不一致都在 content object、derivative 或 current 写入前抛出 `PreviewPolicyError`。
2. 晋升 SQL 自身再次绑定 candidate 的真实状态、source digest 与 content-object digest，同时保留版本号防回退条件。
3. 新增负面回归：把 v1 已存在内容摘要与 v2 candidate versionId 组合调用必须失败，v1 current 不变，candidate derivatives 为 0，preview/thumbnail 元数据也未写入；随后正确摘要仍按单派生物不晋升、双派生物晋升、旧版本不回退通过。

该修复没有改变架构、v2 runtime、数据库迁移、白名单或任何 P02 后继范围；P01 仍为 `in_progress / pending`，等待父级第二次独立复核。

## 实现内容

1. 共享协议保留 `html-template/v1`，新增 `html-template/v2` 联合；v2 的 runtime 只能是 `sandboxed-js` 和精确 `1920x1080` viewport。
2. v2 ZIP 只接受 manifest 精确声明的 UTF-8 HTML/CSS/JS；拒绝外链、未声明引用、父目录/绝对路径、内联脚本/样式、活动导航元素以及伪造或超限 `data:image`。
3. v2 以固定 manifest/slot 字段顺序和 UTF-8 字节序规范化 tags/files/slots/file map，再对规范化 JSON 字节计算 SHA-256；ZIP/manifest 顺序变化不改变摘要，内容变化会改变摘要。
4. 只有版本库 `interactive-template-allowlist.ts` 中的完整小写 SHA-256 可导入。本阶段仅登记仓库内 P01 协议 fixture 摘要 `fb0e964ed926db0c20bb1706044db6e1c52b5ee65dea7d20ae0a3699611e1490`；P05 才可审核并追加十二个真实生成包摘要。
5. 单 HTML 管理员入口继续只生成 v1；v2 只能经管理员 ZIP 路径进入。
6. v2 注册为不可变 verified 候选并排队预览，但不提前更新 `current_version_id`；v1 既有直接登记兼容保持不变。
7. preview 与 thumbnail 只有在同一事务、同一版本真实 source/content digest/renderer version 下完整登记后，才把更高版本号候选晋升 current；迟到的旧版本派生物不会回退 current。
8. v2 运行/iframe/JavaScript 预览仍留给 P02。本阶段当前 v1-only preview worker 会安全拒绝 v2 候选，测试证明失败候选保留原 v1 current。

## 正负门禁证据

- 正向：合法 v1 与白名单 v2 均通过；v2 manifest/runtime、规范化摘要和三类文件清单均被断言。
