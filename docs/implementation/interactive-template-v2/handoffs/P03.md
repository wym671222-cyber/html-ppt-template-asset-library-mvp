## 实现内容

1. Catalog 响应在既有公开 v1/v2 契约、当前版本、`verified/available` 状态及安全 PNG 引用之外，加入 `isCurrent` 和仅对白名单 `html-template/v2` 返回的 `sandboxed-js` runtime mode、精确 `1920×1080` viewport 和同源 BFF runtime URL。响应不包含 CAS digest、相对路径或内部文件系统信息。
2. 详情抽屉只有打开且条目为 v2 时才创建 iframe；关闭、Escape、背景关闭或成功下架都会使 `{#if open && item}` 为假并销毁 iframe 节点。iframe 固定为 `sandbox="allow-scripts"`，绝不包含 `allow-same-origin`、`srcdoc`、blob 或 file 路径。
3. 详情页只接受来自当前 iframe、opaque `null` origin 且匹配 asset/version 的 P02 `ready/error` 事件；拿到 ready 的随机 session 后才发送严格递增 sequence 的精确 replay/reset schema。错误显示为受限 code，卡片仍保持现有 PNG 视觉与路径。
4. 新增同源 Web BFF `POST /api/admin/templates/:assetId/retire`，再精确转发至 loopback API。该写入沿用既有 BFF Origin/JSON/大小限制和 P02 runtime BFF；普通页面 CSP 未改变。
5. API route 要求认证、已激活且无需改密的管理员、精确 asset ID、无查询、`application/json` 以及空 JSON 对象。软下架只将 `template_assets.status` 更新为 `retired`；不删除 TemplateVersion、CAS、派生物或 PresentationItem。重复请求返回 `alreadyRetired: true`，并记录无秘密的 `TEMPLATE_RETIRED`/`ALREADY_RETIRED` 审计事件。
6. 已有 PresentationItem 的读取仍按固定 `template_version_id` 连接不可变版本；新增选择继续要求 active asset。测试证明 retired 条目消失于 catalog、不能新增，但历史引用和已登记派生物记录保持。
