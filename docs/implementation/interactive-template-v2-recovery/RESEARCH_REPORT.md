# 恢复架构证据报告

- 状态：完成
- 核实时间：2026-08-15
- 问题：如何在不放宽恢复校验的前提下跨 PocketBay 版本同步保存 SQLite 备份。

## 已核实事实

- 当前 v1 备份把裸 `database/asset-library.db` 与 manifest、CAS 对象放在目录中；每次读取先校验物理大小和 SHA-256，再校验逻辑状态。
- Release 切换后两个不同时期的裸 SQLite 同时物理失配，一个旧目录缺失；业务数据库、目录和历史汇报仍可读。
- 本地最小差分证明：再次运行应用 migration 不改变备份；对备份 SQLite 做逻辑等价的 page-size/VACUUM 重写会稳定复现相同错误。
- 现有导入/下载已使用受控 stored ZIP，具备文件数、总字节、路径和文件摘要边界，可作为本地密封容器。

## 推断与不确定性

- 最符合证据的原因是平台对裸 SQLite 做物理重写或不完整复制；平台内部实现未被证实。
- 只有真实两版本 `/data` 同步能够证明 ZIP 容器是否保持字节不变，本地测试不能替代生产门禁。

## 采用路线

- 保留 portable manifest v1 和内部文件合同，改变本地持久化形态为单个原子 ZIP。
- 旧目录不迁移、不删除；逐项报告完整性。无效项没有下载、恢复或激活能力。
- 生产以两个运行时代码一致的候选验证平台边界，通过后才开始业务迁移。
