## 交付范围

- `CatalogTransferService` 确定性导出 `asset-library-catalog-transfer/v1` stored ZIP，并以 canonical manifest SHA 派生 transfer ID。
- 暂存前完整验证 ZIP 边界、manifest/对象摘要、模板包、安全策略、slot/current 元数据、PNG 和 renderer pair；通过后以 mode `0600` 原子写入隔离 staging。
- apply 是真正 async 流程：重新验证 staged ZIP，要求 expected manifest SHA 与 target-state SHA，在 SQLite `IMMEDIATE` 事务内执行全部目录 DB 变更。
- 同 ID/同摘要版本幂等复用并同步来源 `status`；manifest 所含版本的 derivative 集合精确同步，目标独有历史版本及其 derivative 保留。同 derivative identity 的内容、安全诊断或时间元数据不一致时 fail closed `409`。来源资产元数据、标签和 current 指针覆盖目标活动目录；目标多出的活动资产仅 soft-retire。
- 受保护表逐表计算 count + content SHA-256，事务前后必须完全一致；固定版本引用、历史汇报、导出记录和 CAS 不删除。
- Hono composition root 注入服务；管理员 API 只有 export/stage/apply 三条精确路由。SvelteKit BFF 同样只有三条精确路由，不新增广域代理。
- `APP_READ_ONLY` 仅允许 stage 继续写隔离文件；apply 在全局中间件和 service 两层均 fail closed，无 bypass flag。

## 负测与数据保护

- 篡改 manifest/file digest、篡改对象字节、路径穿越、重复资产 ID、manifest/ZIP 缺失对象、非法 renderer identity：全部在 staging/DB 前失败。
- immutable version ID/content conflict、asset/version number conflict、stale target-state SHA、read-only apply：精确失败且 DB 无副作用。
- 强制 SQLite trigger 在 apply 中途失败：六张目录表 fingerprint 恢复到 apply 前值，证明单事务回滚。
- 父级驳回后的新增回归：目标 current 版本状态为 `unavailable` 时 diff 为 update、apply 恢复来源 `verified` 并重新出现在目录；来源版本上目标独有的较新 renderer pair 会被移除且目录选择来源 renderer。两者二次 validate 均为 reuse、二次 apply 成功，受保护表 fingerprint 不变。
- derivative 精确同步只在 `IMMEDIATE` 事务内短暂移除 delete guard；必须从精确 trigger 名称的 `sqlite_master.sql` 取得非空定义，并在 `finally` 用该捕获 SQL 原样恢复。自定义格式 guard 在成功、幂等和强制失败/回滚后的 `sqlite_master.sql` 均逐字相同，普通 delete 仍被 append-only trigger 拒绝。匹配 identity 的 content/security/created_at 任一不一致在 validate 阶段返回冲突，不静默覆盖。
- happy path：export 字节确定性、stage 零 DB 写、deterministic diff、apply、软退役保留历史 PresentationItem、再次导入幂等复用。
- 保护数据：users/session/auth throttle/presentation/item/export 都使用非空 fixture，逐表 count 和 SHA-256 在 apply 前后相同；manifest 顶层和 ZIP entry allowlist 证明认证、汇报、恢复或秘密数据不进入包。
- 管理边界：anonymous `401`、member `403`、admin export `200 application/zip`、stage `201`、wrong media `415`、oversize `400`、read-only apply `503 APP_READ_ONLY`。

## 残余风险与后继前置

- composition root 需要运行环境提供精确 40 位 `SOURCE_RELEASE_SHA`；缺失时 export 明确返回 `409`。本阶段未修改生产配置，P05A 必须把冻结候选 SHA 作为部署输入并现场验证 manifest 字段。
