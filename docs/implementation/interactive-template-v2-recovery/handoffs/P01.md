## 产品变更

- `apps/api/src/recovery/local-recovery.ts`
  - 新建与导入统一持久化为 `/data/recovery-backups/<backupId>.zip` 形态的密封 ZIP；最终文件 mode `0600`。
  - 使用同根临时文件、文件 `fsync`、同 ID 提交锁、原子 `rename` 和目录 `fsync`；故障钩子证明 create/import 均不留下半成品或锁文件。
  - sealed 每次读取重新检查 ZIP local/central 文件表、CRC、数量/大小/路径、manifest canonical/hash、SQLite 物理 size/hash、逻辑 hash、quick_check、FK、migration、CAS digest、派生物、汇报和导出索引；archive 下载返回验证后的原始 ZIP 字节。
  - 旧 `backup-*/` 目录保持只读兼容；不迁移、不删除、不覆盖。目录与 ZIP 以唯一受控 ID 聚合，同 ID 双存储为 `conflict`。
  - `RecoveryBackupSummary` 改为 `valid | invalid` 判别联合。invalid 仅有 `id/integrity/storageKind/diagnostic`；列表逐项隔离，无效精确操作 409，missing 404。
  - `MAX_BACKUPS` 统计唯一受控 ID；当前 DB、CAS、backup root 或数量边界异常继续整体 fail-closed。
- `apps/web/src/lib/recovery.ts`、`apps/web/src/lib/recovery-encryption.ts`、`apps/web/src/routes/(app)/admin/+page.svelte`
  - Web 使用同一判别联合；restore/activate/encrypted download 只接受 valid 项。
  - invalid 项只显示泛化隔离文案与存储类型，不渲染 Manifest、下载、恢复或激活控件。

## 固定边界与回滚

- 未改变 portable manifest v1、外部 `.pba` 加密、恢复确认或 session 撤销合同；未降低物理/逻辑/SQLite/CAS 校验。
- sealed 验证每次最多读取并临时物化 128 MiB 归档，这是用额外 I/O 换取不信任持久化字节的 fail-closed 设计。
- 崩溃遗留的 `<backupId>.zip.lock` 不会被当作备份或自动删除；同 ID 后续提交会安全失败，须由后续运维证据判断处理。
- 若父级拒绝本阶段，使用 `git revert <P01-SHA>` 回滚唯一 P01 提交；禁止 destructive reset，且不得删除 `.workbuddy/` 或旧备份。
